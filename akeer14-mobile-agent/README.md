# Akeer14 — عامل Telegram لنظام Android

يحوّل هذا المشروع هاتف Android مخصصًا إلى **عامل مراقبة محلي** يتلقى أوامر Telegram عبر long polling وينفذ عمليات الصور والصوت والفيديو والكشف محليًا، ثم يرسل الأدلة إلى Telegram، أو إلى Gmail كنسخة احتياطية اختيارية. واجهة التطبيق عربية من اليمين إلى اليسار، بينما تظهر لوحات التحكم والأزرار التشغيلية داخل Telegram.

> **تنبيه مهم:** هذا مشروع Android أصلي مضمّن ضمن تطبيق Expo development build. معاينة الويب وExpo Go مناسبان لواجهة الإعداد فقط، ولا يمكن الاعتماد عليهما لاختبار خدمة foreground أو الكاميرا أو الميكروفون أو SMS في الخلفية.

## المزايا الحالية

| المجال | ما يقدمه المشروع |
|---|---|
| Telegram | Long polling محلي، تحقق من Chat ID وUser IDs، لوحات inline keyboard، التقاط صورة وتسجيل صوت وفيديو، ولوحات إعداد وكشف وطوارئ. |
| الأدلة | طابور أوامر أحادي المستهلك، ينتظر انتهاء الالتقاط أو التسجيل، ثم يتحقق من استقرار الملف قبل ضغط صور JPEG أو التسليم. |
| Gmail | نسخة احتياطية اختيارية عبر SMTP؛ لا يُحذف الدليل تلقائيًا عندما تكون النسخة البريدية مفعلة إلا بعد نجاح قنوات التسليم المطلوبة. |
| التشخيص | اختبارات اتصال Telegram وGmail، وفحص فعلي للكاميرا والميكروفون من APK المخصص، وحالة البطارية والاتصال. |
| الطاقة والتنبيهات | تحذير بطارية منخفضة، طلب إيقاف الفيديو بأمان عند أقل من 5% مع انتظار Finalize، ورسائل SMS اختيارية عند فقد الإنترنت أو انخفاض البطارية. |
| الأمان | Bot Token وكلمة مرور Gmail ورقم SMS وإعدادات التنبيه تحفظ في `EncryptedSharedPreferences` على Android، ولا توضع في متغيرات الواجهة أو Git. |

## المتطلبات المسبقة

يلزم تشغيل المشروع محليًا باستخدام Node.js وpnpm، إضافة إلى Android SDK وجهاز Android فعلي أو محاكي يدعم الكاميرا والميكروفون. يجب أن يكون Android SDK مرئيًا لـGradle عبر `ANDROID_HOME` أو الملف `android/local.properties`.

| الأداة | الغرض |
|---|---|
| Node.js وpnpm | تثبيت تبعيات Expo وتشغيل الواجهة والاختبارات. |
| Android SDK وGradle | تجميع طبقة Kotlin الأصلية أو بناء APK محليًا. |
| هاتف Android فعلي | اختبار foreground service والكاميرا والميكروفون والبطارية وSIM وSMS. |
| حساب Telegram Bot | إنشاء Bot Token وChat ID للقناة التي يستقبل منها العامل الأوامر. |
| حساب Gmail اختياري | نسخة أدلة عبر SMTP؛ استخدم كلمة مرور تطبيق عند الحاجة. |

## الاستنساخ والتثبيت

يفترض هذا المثال أن المستودع يحتوي التطبيق داخل المجلد `akeer14-mobile-agent`:

```bash
git clone --branch feat/akeer14-agent-20260824 \
  https://github.com/gbrhomidi/aktbar_project.git
cd aktbar_project/akeer14-mobile-agent
pnpm install
```

لا تنشئ ملفًا يحتوي على Bot Token أو كلمة مرور Gmail داخل المستودع. تُدخل القيم من شاشة إعدادات التطبيق وتُحفظ محليًا بصورة مشفرة في بناء Android المخصص.

## إعداد Android SDK

على Linux، عيّن المسار الفعلي لـAndroid SDK في متغير البيئة، أو أنشئ ملفًا محليًا غير متتبع:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"

cat > android/local.properties <<'EOF'
sdk.dir=/home/USER/Android/Sdk
EOF
```

استبدل المسار في `local.properties` بمسار SDK لديك. لا ترفع هذا الملف إلى Git لأنه يصف جهاز المطور فقط.

## تشغيل الواجهة محليًا

لتشغيل خادم التطوير والواجهة:

```bash
pnpm dev
```

يمكن استخدام الواجهة في المتصفح لمراجعة RTL وإدخال الإعدادات، إلا أن أزرار العتاد والخدمة الأصلية تعرض أن المسار غير متاح في الويب. لا تعتبر نتيجة معاينة الويب تحققًا من وظيفة Android الفعلية.

## تشغيل نسخة Android مخصصة

بعد تثبيت تبعيات Java وAndroid SDK وتوصيل جهاز مدعوم أو تشغيل محاكي، شغّل أحد المسارين الآتيين:

```bash
# بناء وتشغيل نسخة تطوير Android مخصصة على الجهاز أو المحاكي
npx expo run:android

# التحقق من تجميع طبقة Kotlin دون تثبيت التطبيق
cd android
ANDROID_HOME="$HOME/Android/Sdk" ./gradlew :app:compileDebugKotlin --console=plain
```

يمكن كذلك إنشاء APK تجريبي محليًا عبر:

```bash
cd android
ANDROID_HOME="$HOME/Android/Sdk" ./gradlew :app:assembleDebug
```

ينتج ملف debug تحت `android/app/build/outputs/apk/debug/`. لا تعد هذه الخطوة بديلًا عن اختبار الهاتف الحقيقي أو عن توقيع إصدار إنتاجي.

## بناء وتوقيع Release APK

يوفر المشروع السكريبت `scripts/build-release-apk.sh` لبناء ملف Release APK وتوقيعه محليًا. لا ينشئ السكريبت مفتاحًا باسم ثابت ولا يحفظ كلمة مرور في المستودع؛ يطلب القيم بصورة مخفية عند التشغيل التفاعلي، أو يقرأها من متغيرات البيئة في CI محلي موثوق.

أنشئ keystore مرة واحدة في مكان خارج المستودع واحتفظ بنسخة احتياطية مشفرة منه. لا تغيّر alias أو المفتاح بعد نشر التطبيق، لأن التحديثات المستقبلية يجب أن تستخدم التوقيع نفسه.[3]

```bash
# مثال: إنشاء مفتاح محلي خارج المستودع، مع أسئلة تفاعلية لكلمات المرور
keytool -genkeypair -v \
  -keystore "$HOME/.akeer14/akeer14-release.jks" \
  -alias akeer14 \
  -keyalg RSA -keysize 4096 -validity 10000

# يعطي السكريبت أسئلة مخفية لكلمات المرور وينشئ APK ثم يتحقق منه عبر apksigner
export ANDROID_HOME="$HOME/Android/Sdk"
chmod +x scripts/build-release-apk.sh
./scripts/build-release-apk.sh
```

للتشغيل غير التفاعلي، عيّن المتغيرات في مدير أسرار موثوق، لا في سجل الأوامر أو ملف متتبع من Git:

```bash
export AKEER14_KEYSTORE_FILE="$HOME/.akeer14/akeer14-release.jks"
export AKEER14_KEY_ALIAS="akeer14"
export AKEER14_STORE_PASSWORD="..."
export AKEER14_KEY_PASSWORD="..."
./scripts/build-release-apk.sh
```

يضع السكريبت الملف النهائي تحت `dist/apk/release/` ويطبع SHA-256 بعد أن يتحقق `apksigner` من الشهادة. يفشل البناء عمدًا إذا غابت إعدادات التوقيع، ولا يستخدم مفتاح debug لتوقيع نسخة Release.

## إعداد التطبيق من الهاتف الثابت

افتح التطبيق المثبت على الهاتف الذي سيعمل كعامل، ثم اتبع الترتيب التالي:

1. من تبويب **Telegram**، أدخل Bot Token وChat ID، وحدد User IDs المسموح لهم عند الحاجة، ثم اختر **حفظ الإعدادات**.
2. اختر **اختبار اتصال Telegram**. تظهر بطاقة متحركة أثناء حفظ الإعدادات والتحقق، ثم نتيجة نجاح أو فشل واضحة. لا تبدأ العامل قبل نجاح الاختبار أو تشخيص سبب الفشل.
3. فعّل Gmail فقط إذا رغبت في نسخة أدلة بريدية. أدخل خادم SMTP والمنفذ والبريد وكلمة مرور التطبيق والمستلم، ثم اضغط **اختبار اتصال Gmail**.
4. من **التنبيهات**، أضف رقم SMS وفعّل حالات التنبيه المطلوبة. اكتب نصًا منفصلًا لانقطاع الإنترنت ولانخفاض البطارية؛ استعمل الرمز الحرفي `{battery}` في الرسالة الثانية لإدراج النسبة الفعلية.
5. من **التشخيص**، أوقف العامل أولًا ثم شغّل فحص الكاميرا والميكروفون. يلتقط الفحص صورة اختبار قابلة للحذف ويقرأ عينات فعلية من الميكروفون.
6. امنح صلاحيات الكاميرا والميكروفون والإشعارات عند التشغيل. يُطلب إذن `SEND_SMS` فقط إذا فعّلت تنبيهات SMS.
7. اضغط **تشغيل العامل**. يجب أن يبقى إشعار foreground ظاهرًا أثناء تشغيل العامل.

## إعداد Gmail عبر SMTP

القيم الابتدائية المدعومة هي `smtp.gmail.com` والمنفذ `587`. يتطلب Gmail في حسابات كثيرة كلمة مرور تطبيق بدلاً من كلمة مرور الحساب، خصوصًا عند استخدام المصادقة الثنائية. لا تنس اختبار الاتصال من الهاتف؛ نجاح إدخال الحقول لا يثبت صحة بيانات الحساب أو وصوله إلى الشبكة.[1]

## تسلسل الوسائط وحماية الفيديو

لكل أمر دليل، ينفذ العامل المسار بالترتيب التالي:

```text
أمر Telegram → طابور واحد → التقاط/تسجيل → Finalize وإغلاق الملف
→ انتظار استقرار الحجم والتحقق → ضغط JPEG اختياري → Telegram
→ Gmail اختياري → حذف محلي فقط بعد نجاح القنوات المطلوبة
```

أثناء الفيديو، يراقب العامل البطارية. إذا وصلت النسبة إلى أقل من **5%**، يطلب إيقاف التسجيل من CameraX، وينتظر حدث `Finalize`، ثم يمرر الملف الناتج إلى مرحلة التحقق والتسليم. قد يفشل الفيديو إذا انطفأ الهاتف أو أغلق النظام العملية قبل انتهاء التسجيل؛ لذلك لا تعتمد على مستوى بطارية حرج كبديل للشحن الوقائي.

## SMS والاتصال والبطارية

رسائل SMS **اختيارية** ولا تُرسل إلا عند تفعيل الإعداد وإدخال رقم صالح ومنح الإذن. توجد فترة كبح تمنع تكرار التنبيه بكثافة أثناء استمرار نفس المشكلة. اختيار إرسال الرسالة أو قبولها من شبكة شركة الاتصالات ليس مضمونًا؛ افحص الشريحة والرصد والخطة المحلية برسالة اختبار قبل الاعتماد عليها.

يبين تبويب الحالة مستوى البطارية وحالة الشحن والاتصال. يمكن طلب استثناء تحسين البطارية من Android، لكن النظام أو الشركة المصنعة قد ترفض الطلب أو تقيّد الخدمة لاحقًا. تعيد الخدمة sticky التشغيل فقط عند قتلها من النظام، ولا تتجاوز الإيقاف الصريح أو الإيقاف القسري من المستخدم.[2]

## الاختبارات البرمجية

نفّذ الفحوص التالية قبل طلب APK أو تغيير كود Kotlin:

```bash
pnpm check
pnpm lint
pnpm test

cd android
ANDROID_HOME="$HOME/Android/Sdk" ./gradlew :app:compileDebugKotlin --console=plain
```

تغطي اختبارات Vitest عقود أوامر Telegram، الطابور المتسلسل، إعدادات Gmail، مراقبة الصحة وSMS، وحماية الفيديو عند البطارية الحرجة. لا تستطيع هذه الاختبارات محاكاة الكاميرا أو الشريحة أو حسابات Telegram/Gmail الفعلية؛ اختبرها على الهاتف قبل اعتمادها تشغيليًا.

## البنية المهمة

| المسار | الوصف |
|---|---|
| `app/(tabs)/index.tsx` | واجهة RTL: الإعدادات، الاختبارات، التشخيص، التنبيهات، والشروط. |
| `lib/telegram-agent.ts` | جسر TypeScript إلى موديول Android مع تخزين غير حساس فقط. |
| `android/.../TelegramAgentService.kt` | خدمة foreground والـlong polling وطابور الأدلة ومراقبة الصحة. |
| `android/.../AgentConfigStore.kt` | تخزين Android المشفر لإعدادات Telegram وGmail وSMS. |
| `android/.../AgentCameraController.kt` | CameraX للصور والفيديو والتقريب والتحكم بالضوء. |
| `android/.../DeviceHealthMonitor.kt` | حالة البطارية والاتصال وكبح تنبيهات SMS. |
| `tests/` | اختبارات بروتوكول Telegram وعقود طبقة Android. |

## حدود التشغيل والمسؤولية

استخدم العامل فقط على جهاز تملكه أو تملك تفويضًا صريحًا لإدارته. يجب أن تتوافق الكاميرا والميكروفون والتنبيهات وتخزين الأدلة مع القوانين وسياسات المكان الذي يعمل فيه الجهاز. لا يضمن التطبيق استمرار الخدمة إذا أوقفها المستخدم قسرًا أو إذا طبقت الشركة المصنعة قيود طاقة خاصة، كما لا يضمن تسليم Telegram أو Gmail أو SMS دون اتصال وبيانات اعتماد وخدمات خارجية صالحة.
